# 设备适配与控件

设备类别可以帮助选择布局。实际开放的控件取决于该型号的 MIoT Spec、固件上报、当前读值和账号权限。同一类别的不同型号可以拥有不同的大卡片和详情页。

## 哪些设备可设为大卡片

应用和 Windows 桌面共用同一份大卡资格和控件布局，各自保存尺寸与位置。只有经校验的专用布局才显示「设为大卡片」。旧布局中已经展开的普通卡片保留原来的位置和占用空间，缩小后不会再提供展开选项。

| 设备 | 大卡上的内容 | 开放条件 |
| --- | --- | --- |
| 灯、空调（包括部分空调伴侣） | 亮度、目标温度、模式等 | 型号实际提供对应读写项，数值范围或选项有效 |
| 风扇、吊扇、新风、加湿器、除湿机、温控器、音箱 | 风速、模式、目标湿度、目标温度、音量 | 有可识别且可调节的快捷项；需要电源等前置条件时同时校验 |
| 窗帘、卷帘、晾衣架、带适配的扫地机器人和净化器 | 开合、升降、位置、清扫、运行挡位等 | 已知动作、状态和选项能与该型号正确绑定 |
| 多路墙壁开关、中控或继电器 | 逐路开关 | 有 2～4 路可独立绑定的通道；无线键、灵动键及未知模式不可操作 |
| 环境传感器、净水器、冰箱、洗衣机 | 同屏查看温湿度、空气质量、进出水 TDS、分区温度或洗衣状态和剩余时间 | 至少有两项已识别的只读信息；大卡片不发送设置命令 |
| 只提供一个普通开关、一项普通读数或未验证能力的设备 | 保留中、小卡和已有详情 | 例如多数普通插座、单路开关、部分摄像头和厂商私有型号 |

右键菜单只查询型号描述与布局配置，不读设备属性，不新增轮询。保存新大卡尺寸还会在原生端重新校验。已有专用大卡在读值暂时缺失时保留结构；离线和权限限制继续按原有规则处理。

## 详情怎么复用

| 设备 | 共用内容 | 保留的区别 |
| --- | --- | --- |
| 空调、空调伴侣 | 共用空调详情，按型号绑定电源、温度、模式、风速和摆风 | 插座继电器独立控制。型号支持的功率和用电量可直接展示，已验证历史协议的型号提供统计入口。 |
| 风扇、新风机、温湿度调节设备 | 风扇共用运行状态和摆风布局。新风机、加湿器、除湿机和温控器由型号能力提供目标值、模式与风速 | 混合设备按服务分别绑定风扇电源与其他独立开关。 |
| 多路开关、插座、窗帘、卷帘、晾衣架 | 按实际通道绑定电源；使用相同的开合、位置、停止控件类型 | 原有开关模式、动作权限和运动回读校验不变。卷帘样本 `shuse.roller.sr01` 把动作声明在非标准服务中，未启用猜测出的开合命令。 |
| 传感器、净水、家电、媒体、安防 | 标准详情按电源、运动、调节、读数、动作分区；只读及环境、安防等设备优先显示可读数据 | 摄像头媒体、扫地机地图、洗衣程序等专用流程保留。夜灯样本的 Spec 未声明可用照明控制权限，保持只读或空态。 |

## 覆盖范围和核对结果

- 从已安装的米家 APK 11.9.623，用 REA 确认首页按 Spec 和模板选择卡片，不是给所有型号放大相同卡片。包内 `assets/cardControl/control_tiny_layout` 的样本有 70 条记录、74 个类型引用，只有灯的记录含大卡实例 9。云端下发和厂商插件可能覆盖更多型号，APK 内的静态目录不代表全部。
- 2026 年 11 月 20 日，[公开 MIoT `released` 目录](https://miot-spec.org/miot-spec-v2/instances?status=released)快照有 16,360 条记录、15,078 个不同型号、177 个类型。米家 App 的添加分类和 Spec 分类不是同一分组。已有分类中有 165 个类型与公开目录重合、4 个仅在本地分类出现；另补采了公开目录中缺失于本地分类的 12 个类型。来源和样本哈希记录在源码的 `src-tauri/src/fixtures/gallery/PROVENANCE.json`。
- 开发者目录内有 10,879 个型号匹配到公开 Spec。控制项由各型号已验证的描述生成。尚未发布公开描述或依赖厂商专用协议的型号仍可浏览，固件差异和真实设备响应须实机核对。
- 另有 11 个添加入口没有可靠的公开类型对应：手写板、显示器、LED 点阵屏、杯垫、洁面仪、蒸汽眼罩、冲奶器、生态箱、暖宫带、车载音箱、平衡车。配网入口、私有协议和依赖手机硬件的功能不通过猜测来启用。新增型号先用公开 Spec 夹具验证，再补已观察到的私有界面和安全规则。
