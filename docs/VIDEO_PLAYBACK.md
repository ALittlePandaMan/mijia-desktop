# 视频播放与兼容解码

Windows x64 客户端优先使用现有 WebView2 播放路径。系统解码不可用时，随包的 FFmpeg 兼容组件消费同一授权会话的媒体数据，不额外连接摄像头。实时画面、双镜头、监控墙、SD 回放和云端录像共用播放状态与生命周期。

兼容组件支持 H.264、HEVC 及录像所需音轨。它从管道接收现有会话的媒体和尺寸控制记录。Windows Job 限制所有兼容进程的内存和进程数，并在应用退出时结束子进程。支持 CPU 配额的系统也会限制总 CPU 使用率。每路使用一个解码线程。

标准模式下，实时预览保留当前码流的实际分辨率，兼容解码支持现有 4K 安全范围。小窗、监控墙与全屏以相同尺寸解码，窗口和 DPI 改变只调整画面显示区域。1080p 及以下最多 15 帧/秒，更高分辨率最多 8 帧/秒。积压时丢弃已过时的预览帧，持续积压时降低预览帧率，恢复稳定后回升。

监控墙可右键切换分屏。选择较小的分屏可以减少同屏播放路数；监控只连接当前页的摄像头，正在录像、对讲或回看时会阻止切走当前画面。

软件解码进程占满时，画面保留原视频会话并等待解码资源。进程退出后会唤醒等待中的播放器。关闭详情、切页或退出监控会取消等待。实时预览输入积压时从下一关键帧恢复，原始录像继续使用收到的码流。

监控墙的主画面优先使用软件解码进程。名额用满时，双镜头的小窗可以让出解码进程，录像镜头和单镜头全屏继续保留名额。切换主副镜头后，等待中的主画面可从当前会话的关键帧恢复。

前端共享缓冲一次只接收一帧，消费后确认并释放。WebGL 不可用或丢失时使用 Canvas 2D。切换到回看或看家助手时释放隐藏的副镜头，回到实时页面后从新的关键帧开始。高倍速 SD 回看遇到满批数据时提前读取下一批。原始录制和下载保留原始码流。

SD 回看的原生预览队列达到上限后，先送完已经入队的画面。在前端缓冲快用尽时，当前会话从原录像的位置补读。正在进行的录像继续使用原始码流，补读等到录制结束后再进行。

设备详情和监控墙按当前镜头的解码画面判断能否开始录像，Canvas 播放也可以录像。看家助手和门铃云录像按需读取片段，最多预取下一段；导出由后端将原始音视频样本重封装到保存文件。解码不兼容时，当前片段可使用相同数据切换到软件解码，出画后结束加载。播放策略限制和网络错误沿各自错误路径处理。

监控墙隐藏时，原生会话保持连接，并使用摄像头提供的最低画质。返回前台后，从新关键帧恢复画面，并切回每路原来的画质。正在录像、收听、对讲或回看的会话延后降档。

构建输入见 `native/media-decoder.json`，固定 FFmpeg 9.0.2 官方源码哈希。CI 在 Ubuntu 24.04 使用 MinGW-w64 Win32 工具链与系统 NASM 交叉编译 Windows x64 组件；Windows 打包前重新验证哈希、架构与能否正常启动。Windows 本地可用 `scripts/build-media-decoder.ps1`，需要 Git Bash、MinGW-w64 GCC 和 mingw32-make，使用清单中的 NASM 归档。生成目录为 `src-tauri/media-decoder/`，安装包和便携包使用相同的文件清单。

FFmpeg 动态库使用 LGPL-2.1-or-later，不启用 GPL、nonfree 或网络协议。对应源码、许可、构建命令和组件哈希随软件的 `media-decoder/` 目录提供；本项目没有修改 FFmpeg 源码。组件来源：[FFmpeg](https://ffmpeg.org/)，[许可](https://ffmpeg.org/legal.html)。

网络中断、损坏数据、封装错误和解码失败需要分别诊断，不能仅凭黑屏认定缺少 HEVC 扩展。日志只保留错误类型、组件及会话代次，不记录令牌、签名或视频内容。浏览器 Mock 与离线编码样本通过，不代表故障电脑的原生播放已经验收。

Windows 离线探针用 `cargo build --manifest-path src-tauri/Cargo.toml --features media-probe --bin mijia-media-probe` 构建。将已校验的 `media-decoder` 目录放在探针旁，传入离线 MP4 文件和结果 JSON 路径。探针用打包协议加载独立页面，先等 IPC 就绪，再送入样本；它不读取账号、调用摄像头或写设备。

`mijia-media-probe --system <fixture.mp4> <result.json>` 通过 WebView2 的原生视频元素播放同类样本，记录实测分辨率、首帧时间及失败码。
`mijia-media-probe --live-source <fixture.ts> <result.json>` 将离线实时码流送入兼容解码进程，核对送达前端共享缓冲的每帧尺寸。

`python scripts/check-live-decoder-viewport.py <ffmpeg.exe>` 用带 H.264／HEVC 编码器的本地 FFmpeg 生成 720p、1080p、1440p 和 4K 样本，并检查实时原尺寸输出、降帧和回放兼容。生成文件保存在 `.tools/media-build/viewport-fixtures`。
