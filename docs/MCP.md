# 智能家居 MCP

本机 Streamable HTTP 服务按 HyperConnect 2.0.4.577 的智能家居分工实现：Agent 分类、必要拆分和转述，米家云端匹配设备、执行操作并处理关联任务。只提供智能家居，不加载模型、文件协同或 Skill 安装市场，不恢复旧直接控制接口。

在“设置 → MCP”开启服务并选择家庭。现有与新家庭默认勾选，明确排除按账号保留；全部取消时不提交助手请求。地址、端口和 Bearer 密钥沿用原设置。

## 七个工具

本机访问密钥采用预配置 Bearer 请求头，401 附认证挑战；不提供标准 OAuth 自动发现。接入宿主需支持配置 Authorization 请求头。未知工具和无效分页游标返回 JSON-RPC 参数错误；已知工具的业务错误使用 isError。

| 工具 | 用途 |
| --- | --- |
| skills_manage | 仅 readIndex；省略 skillId 返回索引，device-collaboration 返回 Skill 和家庭上下文 |
| tools_search | select:工具名、精确名称或中英文关键词检索，返回真实 Schema |
| get_status | 登录、助手授权、路由能力、家庭数量和回退验证状态 |
| miot_list_devices | 可选 home_id；省略聚合已选家庭，超过 32 KiB 按 cursor 翻页 |
| miot_ask_assistant | query、complexity、UUID requestId 和可选 home_id |
| get_assistant_task | 原 UUID 查询、版本等待和明细分页 |
| cancel_assistant_task | 立即停止本地工作，尽力取消复杂会话 |

七工具始终注册，搜索不激活权限。已可用工具直接调用，不重复搜索。家庭上下文由 Skill 和 mijia://context/v1/selected-homes 资源提供。初始化、Skill、Schema 和生成参考同源版本化。

## 路由与目录

清单、数量、分类、房间和在线概览用 miot_list_devices；普通即时控制、状态和读数用 simple；自动化、场景、知识、故障、摄像头事件等用 complex。业务工具直接调用，搜索、Skill、状态及设备目录不作为逐次控制前置。

明确独立的普通动作可拆分，以不同 UUID 在同一轮并行提交。例如“打开客厅灯，同时打开客厅空调”提交“打开客厅灯”和“打开客厅空调”两个 simple 请求，不等待前一个完成。只保留用户明确的动作和目标，可继承明确共用的上下文。

“关闭客厅灯”“关闭所有灯”各提交一次，不按灯具数量拆分，不提前询问哪几盏灯。顺序、条件、同设备关联或相互影响的请求保持完整：“先打开空调，再设为26度”整体 simple；“温度超过26度才开空调”“开启观影场景”整体 complex。不由 Agent 编排依赖或推测场景动作。

simple 家庭不明时省略 home_id，委托全部已选家庭；指定时只选该家庭。complex 需一个家庭，多家庭且目标不明时仅问一次家庭，使用真实 owner_uid 和全部已选 auth_home_ids。其他澄清只转述云端明确提出的问题。家庭参数不证明服务端强隔离，设备权限/特殊模式交米家云端判断。

目录直接读 MiClaw 只读端点，不加载图片、Spec、卡片或属性。五分钟缓存、请求合并、最多三个家庭并行；不是实时属性测量。家庭上下文 24 KiB，目录分页 32 KiB，截断和部分失败明确标注。独立共享设备仅在无家庭排除且查全部家庭时补充，owner ID 不可作为委托家庭 ID。

## 登录与任务

统一 SSO 使用系统凭据库分别保存账号、mijia、oauth2.0 SID 和助手令牌。新扫码后台连接助手，重启按需恢复；旧合法会话保留，缺少 SSO 时重新验证一次。解除连接持久禁用自动重连；显式重连/登录可以恢复，云端可能要求二次验证。

正常首次登录只扫一个二维码：米家登录成功即进入主页，助手显示“正在连接”，自动完成后变为“已连接”。连接与已连接状态不显示第二个扫码入口。网络、超时或未知协议错误显示“连接失败”，可用“重试连接”复用已保存会话；只有账号凭据缺失、明确失效或安全验证要求才显示“重新验证登录”。状态查询不会重复启动连接，连接失败不会退出米家账号。

发送前保存账号、家庭、UUID、意图和授权代次。同 ID 同参数复用，不同参数冲突。首返五秒，查询/取消不依赖目录联网。重启、超时、断流和未知结果不重放，取消不撤销已发生动作。

原版业务码和 instruction/instructions 格式均兼容。原版回退白名单按分支记录；目前无独立执行前拒绝保证，生产启用数为零，见 mijia://assistant/v1/recovery。不能通过提示词或调用参数启用回退。

任务完成、云端成功和硬件核验分别报告；本接口不独立回读硬件，verification=notPerformed。外部文字不能变成授权或已确认 UI 状态。思考/工具面板由接入宿主决定。

## 默认简短回复

云端答复已简短清楚时直接使用，否则仅简短总结，例如“客厅灯已关闭。”“客厅温度24°C。”不强制添加“米家反馈”前缀。并行结果按用户原句顺序合并，部分失败如实说明；已处于目标状态直接转述，不声称本次产生新动作。不增加耗时、历史推断、故障猜测或建议，复杂问题保留必要的云端答复，不追加自己的分析。

提交和普通任务查询直接返回有界的 `reply`、必要 `devices`，以及任务身份、版本、业务 outcome、来源、云端成功与核验标志、防重放和轮询字段。每个任务完成立即停止，不读设备、不查诊断、不另建请求复核；没有明确答案时如实说明，不自行补救。只轮询未完成的原 UUID，必要答案截断时才读取原任务分页。诊断字段仍兼容，云端结果和持久化记录不因转述而改写。

新版指南为 v5，客户端重新连接后获取初始化说明；Skill、资源和工具说明使用相同规则。独立请求复用现有并发能力，不新增批量工具，也不改变权限声明；外部 Agent 的并行调度、指引遵循情况及思考面板由宿主决定。
